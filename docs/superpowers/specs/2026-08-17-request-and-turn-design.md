# Разбор `submit()`: что уедет модели и чей это заход

Дата: 17.08.2026. Версия на момент замысла: 0.10.0.

Пункт 3 из разбора «что нужно для 1.0.0»: тесты не достают туда, где живут баги.

Цифры на сегодня: `view.ts` — 2457 строк, `main.ts` — 1652, оба без единого
прямого теста; это 42% кода. Один метод `submit()` (`view.ts:1606–1934`) — 339
строк. Из девяти дефектов, починенных за последние пять релизов, семь сидели
внутри него.

Заход **перекладывает код, не меняя поведения**. Дефект, найденный по дороге,
показывается отдельно и чинится отдельным коммитом — иначе в дифф не заглянуть.

---

## Что не так сегодня

`submit()` держит четыре разные заботы, перемешанные построчно:

1. **Сбор запроса** (`1611–1743`) — что именно уедет модели.
2. **Владение лентой** — чей это заход и куда придёт ответ.
3. **Круги инструментов** (`1761–1891`) — цикл обмена с моделью.
4. **Рендер потока** — пузырь, стриминг, кнопки, предупреждения.

Первые две проверяются тестом, только если их отделить. Третья и четвёртая —
сеть и DOM, их и не надо.

### Владение лентой размазано по четырём местам

Одно правило записано четырьмя разными способами:

```ts
const owned = this.host.history.includes(ask);        // 1834, успешный путь
if (current && this.host.history.includes(ask))       // 1962, keepPartial
if (this.host.history[startAt] === ask)               // 1908, кнопка «Повторить»
```

Правило звучит так: пока шёл ответ, ленту могли увести — очисткой, новым
разговором, возвратом по уведомлению, снятием самого вопроса. Ответ, дописанный
в конец после любого из них, встал бы посреди чужого разговора: и в ленте, и в
контексте следующего запроса.

Четвёртое место — то самое, которого не хватало и которое поймало итоговое
ревью 17.08: успешный путь `submit` про правило забыл, хотя у соседних веток оно
было. Пока правило живёт строчкой, которую надо не забыть в очередном месте, его
будут забывать.

### Сборка запроса перемешана с DOM

Посреди вычисления того, что уедет, стоит рисование:

```ts
if (note.clipped) {
  this.listEl.createDiv({ cls: "ai-notice", text: t("chatContextClipped") });
}
```

Поэтому проверить «уедет ли заметка в приватном чате» нельзя, не подняв
Obsidian: функция, решающая это, попутно трогает документ.

### Решения о плашке — там же

Три релиза подряд дефекты приходили отсюда:

```ts
const files = (opts.files === undefined ? (opts.fromEditor ? [] : this.files) : opts.files) ?? [];
if (opts.files === undefined && !opts.fromEditor) this.files = [];
```

Правило «с плашки снимаем только то, что с неё и взяли» стоит рядом с самим
снятием, и каждый новый вызывающий («повторить», «спросить заново», правка
вопроса) начинал с того, что ломал его.

## Часть 1. `src/request.ts` — что уедет модели

Модуль не зовёт API Obsidian: решения принимаются над данными, которые ему
передали. Импорт типов из `attach.ts` при этом допустим — тестовая заглушка
`obsidian` уже собирает и `api.ts`, и сам `attach.ts`.

Два типа переезжают вместе с логикой. **`SubmitOptions`** уходит из `view.ts`
сюда: он описывает заход, а не панель, и за его пределами им никто не
пользуется (проверено — упоминается только в `view.ts`). Безымянный результат
`ChatHost.noteContext()` получает имя **`NoteContext`** в `types.ts`: он ходит
между тремя модулями, и держать его формой-без-имени больше нельзя.

Работа в два шага, потому что вложения читаются с диска, а решение о том, какие
из них вообще нужны, принимается раньше чтения.

### `planRequest(input): RequestPlan` — чистая

Вход — всё, что сегодня берётся из `this`:

```ts
export interface RequestInput {
  text: string;
  opts: SubmitOptions;          // display, system, fresh, fromEditor, quote, files, config
  settings: AiAssistSettings;   // privateChat, tools, systemPrompt; stream не нужен
  history: HistoryItem[];       // лента ДО того, как в неё лёг этот вопрос
  chip: { quote: string | null; files: Attachment[] };   // что лежит на плашке
  note: NoteContext | null;     // заметка-контекст, уже прочитанная вьюхой
  provider: string;             // имя провайдера выбранного config
}
```

Выход — решение целиком, включая то, что вьюхе останется исполнить:

```ts
export interface RequestPlan {
  ask: StoredChatMessage;   // реплика пользователя, как она ляжет в ленту
  files: Attachment[];      // вложения этого вопроса
  clearFiles: boolean;      // снимать ли картинки с плашки
  dismissQuote?: string;    // фрагмент, о котором уже спросили
  priv: boolean;
  canUseTools: boolean;
  system: string;           // склеенный системный промпт (пустой — не отправляем)
  note: NoteContext | null; // заметка, которая реально уедет
  past: StoredChatMessage[];// прошлые реплики в бюджете контекста
  mediaFrom: number;        // индекс в past, чьи вложения уедут (-1 — ничьи)
  notices: RequestNotice[]; // что сказать в ленте ДО запроса
}
```

Правила, которые переезжают сюда целиком, — все из `1611–1743`:

- фрагмент: явный `opts.quote` (включая `null` = «без фрагмента»), иначе с
  плашки; в приватном чате — никогда;
- вложения: явные `opts.files`, иначе с плашки, но `fromEditor` плашку не
  смотрит вовсе;
- `clearFiles` — только когда картинки взяли с плашки и заход не из редактора;
  фрагмент с плашки снимается всегда, каким бы ни был заход (так сегодня и
  работает: `this.attach(null)` стоит без условия);
- приватность: `privateChat && !fromEditor`;
- инструменты: настройка, `!fromEditor`, `!priv` и `toolsAllowed(provider)`;
- системный промпт: подсказка про панель, оговорка «видна ли модели заметка»,
  общий промпт из настроек, разовый промпт действия — в приватном чате остаётся
  пусто;
- заметка в контекст: не при `fromEditor` и не в приватном;
- прошлые реплики: `contextWindow` при `!opts.fresh`;
- картинки прошлых реплик: только у самой свежей, и ни у одной, если к этому
  вопросу приложили своё;
- `resend` у реплики: заполняется, когда показано не то, что уходит.

`RequestNotice` — перечисление, а не готовый текст: перевод остаётся во вьюхе.
Сегодня до запроса рисуется ровно одно предупреждение — обрезанная заметка.
Остальные три (`только размышления`, `ответ оборван`, `круги кончились`)
приходят после ответа и остаются во вьюхе: они не про сборку запроса.

### `assembleMessages(plan, media): ChatMessage[]` — чистая

`media` — словарь по id вложения: готовый `data:`-адрес картинки и/или
разобранный документ. Функция складывает системные сообщения, заметку, прошлые
реплики и текущий вопрос — то, что сейчас делают строки `1699–1743`.

### Что остаётся вьюхе

Единственное, что требует диска: подгрузить медиа для `plan.files` и для
`plan.past[plan.mediaFrom]`, а затем исполнить `clearChip` и `dismissQuote`.

## Часть 2. `src/turn.ts` — чей это заход

Тоже без `obsidian`.

```ts
export interface Turn {
  readonly startAt: number;          // с какого места лента принадлежит заходу
  readonly ask: StoredChatMessage;   // сам вопрос — по нему и опознаём
}

export function beginTurn(history: HistoryItem[], ask: StoredChatMessage): Turn;
export function ownsTurn(history: HistoryItem[], turn: Turn): boolean;
export function rollbackTurn(history: HistoryItem[], turn: Turn): boolean;
```

- `beginTurn` кладёт вопрос в ленту и запоминает место.
- `ownsTurn` — `history.includes(ask)`: лента всё ещё наша. Заменяет три
  разнописанных проверки на одну, и добавить её в новом месте станет дешевле,
  чем забыть.
- `rollbackTurn` — то, что делает кнопка «Повторить»: если по `startAt` лежит не
  наш вопрос, не трогает ничего и отвечает `false`; иначе снимает заход целиком,
  возвращая на место записи журнала правок (правило `dropTalk`), и отвечает
  `true`.

Применяется в четырёх местах: успешный путь `submit`, `keepPartial`, кнопка
«Повторить», и — на будущее — всякий следующий путь записи ответа.

## Часть 3. Что останется в `submit()`

Цикл инструментов, стриминг в пузырь, обработка ошибок, предупреждения после
ответа. Ожидаемый размер — около полутора сотен строк вместо 339.

Порядок внутри метода не меняется: сначала план, потом медиа, потом вопрос в
ленту и на экран, потом запрос. Предупреждение об обрезанной заметке рисуется
там же, где и сегодня, — до запроса.

## Тесты

Новых 50–60, к нынешним 455.

**`planRequest`:** фрагмент явный / с плашки / `null` / в приватном чате;
вложения свои / чужие / из редактора; `clearChip` во всех четырёх сочетаниях;
инструменты при выключенной настройке, у провайдера без function calling, из
редактора, в приватном; склейка системного промпта во всех режимах; заметка в
контексте и её отсутствие при `fromEditor` и в приватном; `past` при `fresh` и
без него; `mediaFrom` — свежая реплика с картинками, вытеснение при своих
вложениях, лента без вложений; `resend` — когда заполняется и когда нет;
предупреждение об обрезанной заметке.

**`assembleMessages`:** порядок сообщений; пустой системный промпт не
отправляется; заметка отдельным системным сообщением; реплика с картинкой и без;
документ и картинка вместе.

**`turn`:** `ownsTurn` после очистки чата, после возврата ленты по уведомлению,
после снятия вопроса кнопкой; `rollbackTurn` — заход снят целиком, записи
журнала остались, чужая лента не тронута, круг инструментов снят вместе с
ответом.

---

## Что НЕ делаем

- Не меняем поведение. Ни одного «заодно поправил».
- Не трогаем `performCall`, `addToolCard`, `waitForDecision` — это цикл
  инструментов, у него своя жизнь.
- Не переносим рендер и не режем `view.ts` дальше: настройки, вложения и
  плашка остаются на месте. Это отдельный разговор.
- Не трогаем `main.ts`: правка из заметки идёт своим путём и `submit()` не
  зовёт.

---

## Проверка

`tsc`, полный прогон тестов, и живой прогон Львом — склейку тесты не видят:

1. обычный вопрос в панели;
2. вопрос с фрагментом на плашке и с картинкой;
3. приватный чат: заметка и фрагмент не уходят;
4. действие из заметки в режиме «показать в панели»;
5. «Повторить» после ошибки — уезжает тот же фрагмент и та же картинка;
6. «Спросить заново» чужой моделью;
7. круг инструментов с подтверждением правки;
8. остановка кнопкой посреди ответа — хвост остаётся в ленте.

## Риск

Рефакторинг живого пути без тестов на нём же. Страховка — в порядке работ:
модули пишутся с тестами до того, как `submit()` начнёт их звать, и переключение
идёт одним куском, а не по кусочку. Если живой прогон найдёт расхождение,
откатывается один коммит.
